Approve without becoming the editor: a lightweight review flow for agent-drafted posts

The fastest way to kill a content cadence is making the founder the unpaid editor-in-chief. The second-fastest is auto-publishing every draft and hoping brand risk stays theoretical.

Small software teams need a third path: explicit approve in minutes, light edits only when something is wrong, and a hard rule that nothing goes live without a recorded yes. That is the edit/approve layer SitePilot runs before publish — usable with markdown PRs or a simple “approve &lt;slug&gt;” reply.

What “approve” is (and is not)

Approve isApprove is not
A named person saying this URL can go liveRewriting every paragraph
A recorded timestamp (PR, email, dogfood sign-off)Silent merge from draft
Room for a short fix listBecoming a second drafting pass
Permission to skip the slotPressure to ship mush to keep a streak

If review regularly takes more than ~15 minutes, the draft failed earlier gates. Fix QA before publish, do not grow the edit ritual.

Mode A — PR review (markdown / Git sites)

Best when the blog is markdown in a repo (docs-as-blog, static site, GitHub Pages).

  1. Agent opens a PR with the draft markdown (or generated HTML + source).
  2. Founder skims H1/H2s, one sample section, and the internal links.
  3. Comment with light edits or approve the PR.
  4. Merge = publish. Record approved_by / approved_at in frontmatter or the PR.

Founder skim checklist (under three minutes):

  • Does the title match a real buyer job?
  • Any claim that feels copied or off-niche?
  • Is there ≥1 useful internal link (product or sibling guide)?
  • Would you send this URL to a customer tomorrow?

If any answer is no, request a rewrite or kill the slot. Do not nitpick commas into a second career.

Mode B — Draft folder + “approve &lt;slug&gt;”

Best when the customer has no Git habit. Drafts live in content/drafts/ (or an email attachment). Customer replies with:

``text approve two-post-week-seo-cadence ``

or

``text edit: soften the pricing paragraph; then approve ``

Agent incorporates the edit, re-runs QA, moves the file to published, and ships. Same rule: no approve signal → no publish.

Mode C — CMS draft (WordPress later)

Create a CMS draft, let the customer tweak in-admin, then flip to publish only after a clear signal. SitePilot’s CMS #1 path is markdown first; WordPress is the fast follow once waitlist votes justify it. Do not run two CMS integrations before the first path has ≥4 dogfood posts with full QA.

Keep the founder out of the drafting chair

Agents (or a contractor) own outline → draft → QA. The founder owns:

  1. Cluster sentence once (who / job / product surface)
  2. Approve or skip each slot
  3. Occasional brand correction (“we never promise X”)

Everything else is ops. If the founder is rewriting openings every week, either the brief is wrong or the pipeline is shipping drafts that should have failed originality / brand fit earlier.

Timing rules that protect cadence

  • Nudge once if no approve within a few business days, then pause that slot.
  • Do not spam-publish to “use” the week.
  • Skip beats dilute — empty is better than a post you would not put your name on.
  • Report the wait in the Monday SEO digest so silence is visible, not mysterious.

A 10-minute review script

  1. Open the draft (PR or preview URL).
  2. Read the opening and every H2 — not every sentence.
  3. Click the internal links; confirm they resolve.
  4. Scan for spam density (repeated keyword walls).
  5. Reply: approve · edit-then-approve · kill.

Done. That is enough accountability for a capped 2-post week without turning product leaders into full-time editors.
